# 충돌 해결 기록

## 충돌 기록 #1: 협업 가이드의 충돌 대응 규칙 통합

### 참여자

- 이지영(L-jy16): 충돌 정보 공유 규칙 작성 및 충돌 해결
- 황승재(bidulgiya999): 충돌 해결 담당자와 공동 확인자 규칙 작성
- 이송하(Leesongha12): PR 리뷰, 최종 병합 및 기록 문서 정리

### 상황과 원인

팀원들이 docs/CONTRIBUTING.md의 충돌 대응 규칙을 각각 수정했다.

이지영의 PR #11이 먼저 main에 병합된 후, 황승재의 PR #13에서 충돌이 확인됐다. GitHub에는 다음 메시지와 함께 병합이 차단된 상태가 표시됐다.

> This branch has conflicts that must be resolved.

- 충돌 파일: docs/CONTRIBUTING.md
- 작업 브랜치: feature/seungjae-conflict-guide
- 병합 대상 PR: #13
- 관련 브랜치: feature/jiyoung-conflict-guide, main

같은 충돌 대응 항목에 서로 다른 변경이 들어가면서 Git이 자동으로 통합하지 못했다.

### 충돌한 내용

- 지영의 변경: 충돌 발생 시 브랜치 이름, 파일 경로, 실행 명령어, 오류 메시지를 공유하도록 규칙 보완
- 승재의 변경: 충돌 해결 담당자와 공동 확인자를 지정하도록 규칙 보완

충돌 당시 마커가 포함된 원문은 현재 기록에 확보하지 못했다. 위 내용은 해결자의 설명을 정리한 것이다.

### 해결 과정

다음은 실제 해결자 이지영의 설명을 바탕으로 정리한 과정이다.

1. PR #13에서 docs/CONTRIBUTING.md의 충돌을 확인했다.
2. 두 브랜치의 변경 내용을 비교했다.
3. 정보 공유 규칙과 담당자 지정 규칙이 모두 필요하다고 판단했다.
4. 두 변경 목적을 함께 반영하는 방향으로 내용을 정리했다.
5. main을 feature/seungjae-conflict-guide에 병합한 커밋 f141f28이 생성됐다.
6. 리뷰 승인 후 PR #13을 main에 병합했다. 최종 병합 커밋은 8f85bd9다.

실제 사용 도구와 세부 명령어·화면 조작 순서는 아직 확인되지 않았다.
안내받은 명령어를 실제 실행 기록으로 대신 기재하지 않았다.

### 해결 전략과 선택 이유

해결 전략은 두 변경의 목적을 함께 유지하는 방식이었다.

충돌 상황을 정확하게 공유하는 규칙은 원인 파악을 돕고,
담당자와 공동 확인자를 지정하는 규칙은 해결 책임과 검토 역할을 명확하게 한다.

서로 보완적인 규칙이므로 한쪽을 삭제하기보다 함께 반영하는 것이
팀 협업에 적합하다고 판단했다.

- PR #13은 main에 정상적으로 병합됐다.
- 최종 문장 원문과 구체적인 검증 절차는 추가로 보완한다.

### 배운 점과 주의점

- 같은 문서의 같은 부분을 수정하면 병합 시 충돌이 발생할 수 있다.
- 충돌 해결 시에는 양쪽 변경의 목적을 확인해야 한다.
- PR 승인과 리뷰 대화 해결은 파일 충돌 해결과 별개의 절차다.
- 다음 실습부터는 충돌 마커 원문, 실제 조작 순서, 해결 전후 문장을 즉시 기록한다.
- 공유 브랜치의 히스토리를 강제로 변경하지 않고 병합 커밋과 PR로 기록을 남긴다.
