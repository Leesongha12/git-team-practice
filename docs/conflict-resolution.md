# 충돌 해결 기록

## 충돌 기록 #1: 협업 가이드의 충돌 대응 규칙 병합

### 참여자

- 이지영(L-jy16): 충돌 정보 공유 규칙 작성 및 충돌 해결
- 황승재(bidulgiya999): 충돌 해결 담당자와 공동 확인자 규칙 작성
- 이송하(Leesongha12): PR 리뷰, 최종 병합 및 기록 문서 정리

### 상황과 원인

팀원들이 `docs/CONTRIBUTING.md`의 충돌 대응 규칙을 각각 수정했다.

이지영의 PR #11이 먼저 `main`에 병합된 후, 황승재의 PR #13에서 충돌이 확인됐다. GitHub에는 다음 메시지와 함께 병합이 차단된 상태가 표시됐다.

> This branch has conflicts that must be resolved.

- 충돌 파일: `docs/CONTRIBUTING.md`
- 작업 브랜치: `feature/seungjae-conflict-guide`
- 병합 대상 PR: #13
- 관련 브랜치: `feature/jiyoung-conflict-guide`, `main`

같은 충돌 대응 항목에 서로 다른 변경이 들어가면서 Git이 자동으로 통합하지 못했다.

### 충돌한 내용

- 지영의 변경: 충돌 발생 시 브랜치 이름, 파일 경로, 실행 명령어, 오류 메시지를 공유하도록 규칙 보완
- 승재의 변경: 충돌 해결 담당자와 공동 확인자를 지정하도록 규칙 보완

충돌 당시 마커가 포함된 원문은 현재 확보하지 못했다. 위 내용은 해결자의 설명을 정리한 것이며, 실제 충돌 마커 원문을 대신하는 것은 아니다.

### 해결 과정

다음은 실제 해결자 이지영의 설명과 확인된 병합 기록을 바탕으로 정리한 과정이다.

1. PR #13에서 `docs/CONTRIBUTING.md`의 충돌을 확인했다.
2. 두 브랜치의 변경 내용을 비교했다.
3. 정보 공유 규칙과 담당자 지정 규칙이 모두 필요하다고 판단했다.
4. 해결자는 두 변경 목적을 함께 반영하려 했다고 설명했다. 다만 병합 후 확인한 충돌 대응 항목에는 담당자 지정 규칙만 남아 있어, 정보 공유 규칙의 누락 여부를 추가 확인 중이다.
5. `main`을 `feature/seungjae-conflict-guide`에 병합한 커밋 `f141f28`이 생성됐다.
6. 리뷰 승인 후 PR #13을 `main`에 병합했다. 최종 병합 커밋은 `8f85bd9`다.

실제 사용 도구와 세부 명령어·화면 조작 순서는 아직 확인되지 않았다. 안내받은 명령어를 실제 실행 기록으로 대신 기재하지 않았다.

### 해결 의도와 선택 이유

해결자의 설명에 따르면, 의도한 전략은 두 변경의 목적을 함께 유지하는 것이었다.

충돌 상황을 정확하게 공유하는 규칙은 원인 파악을 돕고, 담당자와 공동 확인자를 지정하는 규칙은 해결 책임과 검토 역할을 명확하게 한다.

두 규칙은 서로 보완적이므로 함께 반영하려고 했다. 다만 이 의도가 최종 파일에 모두 반영된 것은 확인되지 않았으며, 병합 결과와 설명 사이의 차이를 확인 중이다.

### 결과

- PR #13이 `main`에 병합되었다.
- 최종 병합 커밋: `8f85bd9`
- 해당 커밋의 `docs/CONTRIBUTING.md`를 확인한 결과, 충돌 해결 담당자와 공동 확인자를 지정하는 규칙이 반영되어 있었다.
- 다만 `충돌 대응` 항목에서는 브랜치 이름, 파일 경로, 실행 명령어, 오류 메시지를 공유하는 구체적인 규칙을 확인하지 못했다.
- 해결자는 두 변경 사항을 함께 보존하려는 의도였다고 설명했으나, 최종 반영 내용과 차이가 있어 추가 확인이 필요하다.
- Git의 병합 충돌이 해소된 것과 양쪽 변경 의도가 모두 보존된 것은 별도로 검증해야 함을 확인했다.

### 최종 반영 문장 확인

최종 병합 커밋 `8f85bd9`의 `docs/CONTRIBUTING.md`에서 충돌 대응 첫 번째 항목을 다음과 같이 확인했다.

> 1. 충돌이 발생하면 PR 작성자를 해결 담당자로 정하고, 같은 파일을 수정한 팀원을 공동 확인자로 지정한다.

해당 항목에는 담당자와 공동 확인자 지정 규칙이 반영되어 있다.

### 결과 확인에 사용한 명령어

다음 명령어는 충돌 해결 당시 실행한 명령어가 아니라, 기록 작성 과정에서 최종 병합 결과를 확인하기 위해 실행한 명령어다.

```powershell
git --no-pager show 8f85bd9:docs/CONTRIBUTING.md
```

### 후속 확인

이송하가 PR #13에 이지영을 멘션하여 다음 사항을 확인 요청했다.

1. 정보 공유 규칙을 다른 위치에 남겼는지, 충돌 해결 과정에서 누락했는지
2. 실제 충돌 해결에 사용한 도구와 실행 명령어 또는 화면 조작 순서

답변을 받은 후 실제 해결 절차와 누락 여부를 이 문서에 보완할 예정이다. 추가 수정이 필요한 경우 기존 병합 기록을 변경하지 않고 새로운 커밋과 PR로 수정 과정을 남긴다.

### 배운 점과 주의점

- 같은 문서의 같은 부분을 수정하면 병합 시 충돌이 발생할 수 있다.
- 충돌 해결 시에는 양쪽 변경의 목적을 확인해야 한다.
- 충돌 경고가 사라졌더라도 필요한 내용이 빠지지 않았는지 최종 파일을 확인해야 한다.
- 해결자의 의도와 실제 파일에 반영된 결과를 구분해서 기록해야 한다.
- PR 승인과 리뷰 대화 해결은 파일 충돌 해결과 별개의 절차다.
- 다음 실습부터는 충돌 마커 원문, 실제 조작 순서, 해결 전후 문장을 즉시 기록한다.
- 공유 브랜치의 히스토리를 강제로 변경하지 않고 병합 커밋과 PR로 기록을 남긴다.
